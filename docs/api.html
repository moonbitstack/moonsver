suberrorRefused#

Why a version or a range was refused, and where.

at is the zero-based character index of the first offending character, or the input's length when it ended early; the message says what was expected.

pub(all) suberror Refused {
  • Empty(at~ : Int32, String)Empty input where the grammar wants a version or a range.
  • Unexpected(at~ : Int32, String)A character that does not belong where it stands.
  • Truncated(at~ : Int32, String)The input ended partway through.
  • Number(at~ : Int32, String)A numeric component that is not a number.
  • LeadingZero(at~ : Int32, String)A numeric component, or a numeric prerelease identifier, with a leading zero (SemVer 2.0.0 §2, §9).
  • EmptyIdentifier(at~ : Int32, String)An empty identifier, as in 1.0.0- or 1.0.0-a..b.
  • Identifier(at~ : Int32, String)An identifier with characters §9 and §10 do not allow.
  • Unsupported(at~ : Int32, String)A spelling the chosen Syntax does not accept.
  • Range(at~ : Int32, String)A range that does not hang together, such as a concrete part after a wildcard.

Implements Show.

enumPrereleasePolicy#

How prereleases are matched against a range.

The spec only orders prereleases against each other; it says nothing about how a range should treat them, so every ecosystem settled on its own convention.

pub(all) enum PrereleasePolicy {
  • SameTupleThe npm and Cargo convention: a prerelease can only satisfy a set when some comparator carries a prerelease with the same major.minor.patch. So >=1.2.3-alpha takes 1.2.3-beta but not 1.2.4-beta, and * takes no prerelease at all.
  • AlwaysTreat prereleases as ordinary versions (npm's includePrerelease).
  • NeverPrereleases never match anything, for when only stable releases will do.

Implements Eq.

enumRelease#

structSyntax#

Range grammar settings.

A version has one spelling in SemVer 2.0.0, but ranges are not in the spec, and different ecosystems settled on different rules. Their differences are settings here, so one parser can read several grammars.

Switches that govern version literals:

  • allow_v_prefix: accept v1.2.3
  • allow_equals_prefix: accept =1.2.3 as a version literal
  • allow_build_metadata: accept a +build segment
  • trim: allow whitespace around a version literal

Switches that govern range syntax:

  • default_op: what a bare version means (npm Exact, Cargo Caret)
  • tilde_bump: how ~ finds its upper bound (npm/Cargo Patch, Ruby LastSpecified)
  • allow_caret / allow_tilde: accept ^ / ~ (~> only under LastSpecified)
  • allow_ne: accept !=
  • allow_or: accept ||
  • allow_hyphen_range: accept 1.2.3 - 2.0.0
  • allow_xrange: accept the shorthand forms 1.x, 1.2.* and bare 1.2
  • allow_empty: whether an empty string means "any version"
  • prerelease_policy: how prereleases are matched
pub(all) struct Syntax {
  • allow_v_prefix : Bool
  • allow_equals_prefix : Bool
  • allow_build_metadata : Bool
  • trim : Bool
  • default_op : DefaultOp
  • tilde_bump : TildeBump
  • allow_caret : Bool
  • allow_tilde : Bool
  • allow_ne : Bool
  • allow_or : Bool
  • allow_hyphen_range : Bool
  • allow_xrange : Bool
  • allow_empty : Bool
  • prerelease_policy : PrereleasePolicy

Implements Default, Eq, Show.

rubymethod#
pub fn Syntax::ruby() -> Self

Ruby grammar: ~> is the pessimistic operator (drop the last segment, then bump), and != is allowed; no ^, ||, hyphen ranges or shorthand.

strictmethod#
pub fn Syntax::strict() -> Self

Strict SemVer 2.0.0 spelling: only = > >= < <=, joined by commas or spaces, with no ^, ~, ||, hyphen ranges, 1.x shorthand or v prefix.

The one exception is *, which always means "any version": it is what Range::to_string prints for an empty range, so refusing it would break the round trip.

enumTildeBump#

How ~ and ~> work out their upper bound.

pub(all) enum TildeBump {
  • Patchnpm and Cargo: bump the minor if one was written, otherwise bump the major. - ~1.2.3 → >=1.2.3 <1.3.0 - ~1.2 → >=1.2.0 <1.3.0 - ~1 → >=1.0.0 <2.0.0
  • LastSpecifiedRuby's ~>: drop the last segment, then bump whatever is left. - ~> 1.2.3 → >=1.2.3 <1.3.0 - ~> 1.2 → >=1.2.0 <2.0.0 - ~> 1 → >=1.0.0 <2.0.0

Implements Eq.
